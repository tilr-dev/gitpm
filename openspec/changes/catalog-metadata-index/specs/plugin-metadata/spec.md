## MODIFIED Requirements

### Requirement: Metadata in the catalog
Because a catalog release carries the whole manifest (catalog, "Release record"), `catalog-update` and `register` SHALL publish the metadata. A catalog written by this version SHALL also publish each plugin's latest-release metadata in a per-plugin summary that `info` and `browse` read instead of one `release.json` per plugin; a catalog without it SHALL still be browsed by reading `release.json` (at most 40). Catalogs SHALL stay readable by gitpm 0.4 and 0.5.

#### Scenario: info shows metadata
- **WHEN** the latest release of `tilr/theme` has a title and provides
- **THEN** `gitpm info` prints `Title: Theme` and `Provides: theme` under the plugin

#### Scenario: Overview without per-plugin release reads
- **WHEN** an HTTPS catalog generated by this version lists 40 plugins
- **THEN** `browse` shows their metadata without requesting any `release.json`

#### Scenario: Older client
- **WHEN** gitpm 0.5 reads a catalog generated by this version
- **THEN** it browses and installs as before
