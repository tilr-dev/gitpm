# Untrack the generated spec coverage report

## Why

`openspec/coverage/coverage.md` and `coverage.json` are regenerated by every `./itests/dt coverage` run and change whenever a task touches tests or specs, so committed copies conflict between task PRs (the owner's 2026-10-20 decision, TILR-173). The hand-written `atq.md` that used to live next to them was already moved into the specs and deleted (TILR-174), so the whole `openspec/coverage/` directory is now generated output.

## What Changes

- Remove `openspec/coverage/coverage.md` and `coverage.json` from Git and ignore the whole `openspec/coverage/` directory.
- The `integration-tests` "Coverage report" requirement states that the report is a local artifact: written on demand, ignored by Git, never committed.
- README and `itests/README.md` say the report is local and not committed.

## Non-goals

- Changing the report's content, format or the generator (`itests/tools/coverage.py`) beyond its docstring.
- Changing gitpm CLI, library, FFI or file-format behavior.

## Impact

Repository layout and documentation only. `./itests/dt coverage` keeps writing the same files to the same place; they just no longer show up in `git status`.
