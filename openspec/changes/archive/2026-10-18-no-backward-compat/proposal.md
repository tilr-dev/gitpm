# Proposal: No backward compatibility before 1.0

## Why

The owner decided on 2026-10-18 (decision D1, TILR-38) that gitpm keeps no backward compatibility before 1.0. The code still carries several compatibility paths that the specs describe as current behavior: legacy unscoped IDs and `vVERSION` tags (spec `package-ids`), state.json format 1 read and rewritten as format 2 (`workspace-layout` "State format versions"), v1 monolithic catalogs and `migrate-catalog` (`catalog` "v1 catalogs stay readable"), the CLI alias `create` for `init`, and metadata read from the clone for records of gitpm 0.4 (`plugin-metadata` "Metadata in state"). `gitpm-ffi` keeps its own version 0.1.0 (review finding G3#12). The same day the owner decided (TILR-43) that the Plugin → Package rename of the library, FFI and state lands here, in the same format bump: the specs say "package" while the API says `InstalledPlugin`, `PluginManager`, `plugins` (cross-spec review, section "Terms"). Fork repositories get the Git config keys `pm.forkBase`/`pm.forkVersion`, which nothing in gitpm reads (TILR-105; only tests assert them).

## What Changes

- **BREAKING** Package IDs are always `namespace/name`; unscoped IDs fail with `invalid_id`. `update all` can no longer collide with an ID `all`. Migration: re-create the package under a namespace.
- **BREAKING** Release tags are only `ID@VERSION`; `vVERSION` tags are not releases (single- and multi-package repositories). Migration: tag `ID@VERSION`.
- **BREAKING** `state.json` other than the current format is refused with `unsupported` and never rewritten. Rule: the format is bumped whenever an older gitpm would misread the content; there is no migration. This change makes format 3 current (state key `packages`). Migration: re-create the workspace.
- **BREAKING** Plugin → Package rename (TILR-43): library types and fields `Plugin*` → `Package*` (`InstalledPlugin` → `InstalledPackage`, `PluginSummary` → `PackageSummary`, …), `state.plugins` → `state.packages` (format 3), the workspace folder of own clones `plugins/` → `packages/`, messages say "package" instead of "plugin"; FFI `PluginManager` → `PackageManager`, `InstalledPlugin` → `InstalledPackage` and the other records, Swift/Kotlin bindings regenerated by `scripts/build-apple.sh`. The manifest file name stays `plugin.json`. Migration: rename in host code; re-create workspaces.
- **BREAKING** v1 catalogs and `migrate-catalog` are removed; `legacy/<id>/` and releases without file hashes are gone. With one catalog format left, `catalog::CatalogFormat` and `CatalogOverview.format` (library and FFI) are removed and `info` prints no `Format:` line. Migration: regenerate the catalog with `catalog-update`.
- **BREAKING** CLI alias `create` is removed (`init` only).
- `list` reports metadata only from the state record (no clone fallback for 0.4 records).
- A new fork no longer gets the unread Git config keys `pm.forkBase`/`pm.forkVersion` (TILR-105); `forkOf` in the manifest is the only fork provenance.
- `gitpm-ffi` carries the library version (release-please updates it with `gitpm`/`gitpm-cli`); the FFI promises no stability before 1.0.
- Release note: this change and the eleven that follow it in the chain ship together as one release, 0.6.0, after `robustness-fixes` (owner decision of 2026-10-18); README "Changed in 0.6" collects their BREAKING entries.

Depends on: none (first of the 2026-10-18 chain: `no-backward-compat` → `thin-cli-boundary` → `check-via-origin` → `single-ref-mode` → `download-and-enable` → `update-all-skips-broken` → `removal-and-restore-rules` → `no-tag-immutability` → `protected-catalog` → `pre-release-versions` → `host-compatibility` → `robustness-fixes`).

## Capabilities

### Modified Capabilities
- `package-ids`, `multi-package-repos`, `workspace-layout`, `catalog`, `cli`, `authoring`, `errors`, `dist`, `plugin-metadata`, `release-process`, `ffi-bindings`, and (rename of literal names and messages only) `transactions-locking`, `install-uninstall`, `dependencies`, `package-manifest`, `updates`.

## Out of scope

- Any migration tool, alias or deprecation window.
- The `PM_*` variables (already ignored).
- Renaming the manifest file `plugin.json`, the catalog file `namespaces/<ns>/<name>/plugin.json` or the capability name `plugin-metadata`.
- Host (Tilr) code that uses the renamed FFI names.

## Impact

`identity.rs`, `model.rs` (ID, state format 3, `packages` key, renamed types), `releases.rs`, `catalog.rs` (v1 reader, `migrate`, legacy paths), `check.rs`/`model.rs` metadata fallback, `workspace/fork.rs` (no `pm.*` config), every library message that says "plugin", CLI command table and help, `crates/gitpm-ffi` (renamed objects and records, `uniffi.toml`, `Cargo.toml`) and `scripts/build-apple.sh`, `release-please-config.json` extra-files, README "Changed in 0.6", Dagger cases using legacy IDs, `v*` tags, `create`, `migrate-catalog`, `plugins` in state or `pm.forkBase`, `openspec/config.yaml`. Tracker: TILR-38, TILR-43, TILR-105.
